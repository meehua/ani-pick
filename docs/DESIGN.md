## 0. 一句话定位

AniPick 是一个以本站索引库为准的多源作品检索站：**抓取期**从各上游拿数据入库，
**访问期**（页面与 API）只读本站库，不回任何上游。

## 1. 最高原则

1. **本站接口只响应自己的库。** 任何端点不得在请求路径上调用上游；上游数据唯一
   入口是抓取管线。页面要展示的字段必须在抓取期入库（简介、官方外链等）；库里
   没有的展示能力不做。例外：访客浏览器直连 bgm API（凭据不出本机、不经过本站
   接口）。
2. **业务参数不写死。** 可调数值进系统设置（带默认值与建议文案），来源语义进
   登记表声明，env 只留引导与基础设施；代码不出现业务专名与魔法数。
3. **拿不准就拒绝。** 合并歧义拒绝；可信网段校验 fail-closed；设置键越清单拒绝。
4. **源原生词表神圣。** 各源自己的类型叫法不被站点改名；站点分类是独立的 kind 层，
   两层并存。

## 2. 数据模型与身份

- `subjects` 一行 = 一个上游记录，以 `(source, source_ref)` 唯一定位。bgm 行的 id
  沿用 bgm 主键；扩展源行 id 从 1e10 序列分配，公开 id 一经分配永不变。
- `work_id` 作品分组：同作品跨源归为一组，组内主行 id 即 work_id；检索塌缩条件
  `work_id = 0 OR id = work_id` 在部分索引谓词里（迁移 0008）。
- `ext_key` 确定性键：AniList 与 MAL 共用 MAL id 空间，写库时完成互配。
- 评分两层口径：`raw_score`/`raw_rating_total` 是各源自己的原始值，不被覆盖；
  主行 `score`/`rating_total` 是按管理员权重合成的作品值。展示时两者分开。
- 内部字段不出服务：`source_ref`、`work_id`、`ext_key`、`alt_titles` 的 JSON 标记
  为 `-`；对外需要的派生值（官方外链）由服务端拼好后下发。
- 存量数据补字段靠增量抓取、过期重爬与管理端单条刷新回填。

## 3. 来源登记表（internal/registry，叶包）

新增或修改来源的唯一声明点，store 与 sources 都依赖它。声明内容：类型词汇
（编码→原生标签）、kind 归并、评分换算满分、官方外链模板（`{ref}` 占位）、抓取
预算（页大小/页数/标签门槛/地区）、凭据字段与校验能力、抓取模式能力清单。
服务端经 `/api/meta` 下发 manifest，前端词表（`frontend/src/api/vocab.ts`）
零硬编码——前端不自带任何来源语义。

**新增来源检查清单**：适配器（Harvester，含真增量路径）→ 凭据声明与校验器 →
登记表条目 → 简介随抓取入库 → 测试（增量/空数据升级/凭据校验/入库字段）→
manifest 字段核对。接入前对照 §1 逐条检查，与原则冲突的做法先改本文再动手。

## 4. 抓取管线

发现（榜单或日期窗口）→ 归一化 → `UpsertSubjects`（身份收口/作品匹配/写库）
→ 合成评分重算。

- **真增量**：按上游能力选开播/上映日期窗口或播报榜头部；空数据（该源从未完成
  过增量）自动按全量预算补齐。
- **过期重爬**兜底上游变更：保留期全局默认 + 每源覆盖。
- 抓取收尾钩子统一失效列表类缓存并 `VACUUM ANALYZE`；失效靠钩子，TTL 只是兜底。
- 调度（间隔 / 每日定点 / 隔 N 天定点）存设置；锚点 = 上次自动轮。

## 5. 作品合并（store/workmatch）

三级匹配：同引用 → `ext_key` → 标题归一 + 年份容差 + 同类。同源不互并；
打平拒绝。冲突按有效源优先级归类，同级仍拒绝。匹配组是多对多的类型匹配
（决定哪些来源的哪些类型之间允许配对），组的排列不影响匹配。

## 6. 性能与缓存

契约以 [AGENTS.md](../AGENTS.md)「性能红线」为准：响应压缩不许绕过、热点查询
必须 TTL 缓存、失效钩子优先于 TTL、单飞合并回源、meta/概览过期走后台刷新
（先回旧值再单飞重算，轮询不等库）、进程内缓存必须带上限、禁 N+1。
统计查询必须可走索引；新的塌缩类过滤条件做进索引谓词。

## 7. 明确不做的事

- 不做任何 API 中继、图片代理、反向代理、详情代理。
- 不在 handler 写死 TTL 或业务数值；公共层不出现业务专名。
- 不静默挑一个歧义匹配；错误文案不给走不通的修复建议。
- 迭代中间态不进仓库；一个任务一个提交，未推送的修正折回原提交。
